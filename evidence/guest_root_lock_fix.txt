GUEST-ROOT _lock 500: ROOT CAUSE, REPRODUCTION, AND FIX
=======================================================
Measured 2026-07-26 on jac 0.34.7 / macOS arm64, against a full copy of this
repo at /tmp/ab-scale. Nothing here is inferred from symptoms; the mechanism
was read out of the jaclang runtime that ships inside the `jac` binary
(~/.cache/jac/rt/13d383ad3c816638-*/site/jaclang) and then reproduced.

MECHANISM
  jac0core/runtime.jac:85  _scale_provider   -> bare try/except ImportError,
      no jac.toml gate, and jaclang.scale ships inside the binary. The scale
      subsystem therefore loads ALWAYS.
  scale/identity/impl/user_manager.impl.jac:1  JacScaleUserManager.postinit
      overrides UserManager.postinit and never calls it.
  runtimelib/impl/server.impl.jac:12  UserManager.postinit is the ONLY place
      that sets `self._lock = threading.RLock()`.
  => the scale user manager has no _lock at all, from boot.
  runtimelib/impl/server.impl.jac:271  _abegin_user_request_context - when the
      guest root anchor is missing it logs "Guest root anchor <id> is missing
      from the anchor store" and calls reset_root() at line 305.
  runtimelib/impl/server.impl.jac:80  UserManager.reset_root is NOT overridden
      by the scale subclass, and its first statement is `with self._lock`.
  => AttributeError -> HTTP 500. reset_root IS the repair path, so it can never
     repair itself: every subsequent request takes the same branch forever.

  Doubly broken: even with _lock present, reset_root does `SELECT 1 FROM users`
  against main.db, while scale keeps identities in .jac/data/users.db
  (SqliteIdentityStorage). The guest heal path cannot work under scale at all.
