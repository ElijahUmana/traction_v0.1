THREE DEFECTS, ALL ONLY VISIBLE OVER HTTP

1. jid -> jobj round-trip 500'd.
   A `flow` thread does not inherit the walker's GUEST-root binding, so
   jobj() could not see a Lane created microseconds earlier. Fixed by passing
   the node itself. Under `jac run` the local root is ambient, so it resolved.

2. A node-typed `has` field is always OpenAPI-`required`.
   `has run: any = None` AND `has run: ResearchRun | None = None` both land in
   `required`, so a `{}` POST 422'd before the walker ran. Now a jid string.

3. Threads can MUTATE guest-root nodes but cannot ATTACH new ones.
   Each lane reported 9 probes and lane.state=dry was visible, while every
   Reasoning the thread created was invisible - an empty analyst sidebar.
   Fixed by buffering in the thread and flushing from the orchestrator after
   `wait`. Parallelism is unaffected: the browser I/O still runs concurrently,
   only the writes are serialised.
