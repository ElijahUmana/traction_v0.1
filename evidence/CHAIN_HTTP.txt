THE CHAIN, OVER HTTP — captured by ops/chain.sh
================================================================================
Captured by DEMOPATH against an ISOLATED instance (port 8902, data dir
/tmp/demopath-data), not the demo server on :8000. Anonymous POSTs throughout —
no Authorization header is sent anywhere in the script.

WHY THIS ARTIFACT EXISTS
Every segment of TRACTION had a strong individual proof, and all of them were
`jac run` proofs. `jac run` writes the LOCAL root; the server reads the GUEST
root. So a walker can be green under `jac run` and dead over HTTP. This run is
the first time the whole chain has been driven over HTTP with the GRAPH read
back at every boundary. It found two defects that every prior proof missed.

HOW TO READ IT
Every stage prints a census read out of the server with `graph_health`, plus a
MOVED / (no change) line. A stage that reports success without moving a count is
a FAILED stage here, whatever it returned. Walker return values are never
treated as proof.

WHAT THIS RUN PROVES
  - `walker:pub` genuinely opens anonymous access. Negative control below.
  - The Vapi mid-call tool envelope is defeated: `/vapi/kb` and `/vapi/book`
    return exactly {"results":[{"toolCallId":"...","result":"<string>"}]}.
  - `RunResearch`'s `from_root` Root entry fires over HTTP against the guest root.

WHAT THIS RUN DISPROVES  ** READ THIS BEFORE TRUSTING ANY GREEN CHECK **
  - `POST /walker/RunResearch {}` -> HTTP 422. `has run: any = None` emits no
    default into the OpenAPI schema, so the field is marked REQUIRED.
  - `POST /walker/RunResearch {"run": null}` -> HTTP 500 in 0.087s, graph
    unmoved. `resolve_lane` (research.jac:1342) calls `jobj(lane_jid)` inside a
    `flow` worker thread; the thread does not inherit the request's guest-root
    binding, so the Lane created microseconds earlier does not resolve.
    THE DASHBOARD'S GO BUTTON DOES NOT WORK OVER HTTP. Unfixed at capture time.

STARTING GRAPH STATE
This was the third chain run against this instance, so the graph already carried
founders=1 runs=2 lanes=10 from earlier runs' intake seeding. That is why the
census starts non-zero. It does not affect any conclusion: every conclusion here
rests on the DELTA at each boundary, and RunResearch's delta is (no change).

INSTANCE CAVEAT — STATED SO NOBODY IS MISLED
`main.jac` imports thirteen names from `bridge`, and `bridge.jac` did not exist
when this instance was booted (`No module named 'bridge'`, main.jac:84). To get
a server at all, DEMOPATH placed a LOCAL-ONLY stub `bridge.jac` in the isolated
copy whose every function RAISES. It is not committed. Nothing in this chain
calls the bridge — the script drives walkers directly over HTTP — so the stub
does not touch any result below.

    /walker/LaneA         security=[{"BearerAuth":[]}]
    /walker/ResolveEmail  security ABSENT
  Anonymity is genuinely gated on this server, and `:pub` is what opens it.

marked required; every other field carries its declared default.

--- 3. the `from_root` Root entry DOES fire over HTTP --------------------------

  A non-empty reports array from the Root entry, against the guest root. That is
  the ability firing — not the old silent `200 []` no-op. JACCDP's fix is real;
  it is defect 2 and defect 3 above that stop it being reachable.
